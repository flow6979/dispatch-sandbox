# Repository Orientation: `dispatch-sandbox`

## What this repo is

`dispatch-sandbox` is a **throwaway test repository** used to exercise **Dispatch**, an
automated task-execution runner. It is not a product, library, or application — it exists
purely as a safe target where Dispatch can perform real actions (creating branches, making
commits, opening pull requests) against a live GitHub repository without touching anything
that matters.

Think of it as a scratchpad / integration-test harness for the Dispatch system itself.

## The problem it solves

To validate that an automated agent runner works end-to-end, you need a real repository it
can act on — one where mistakes are harmless. `dispatch-sandbox` fills that role:

- It gives Dispatch a **real Git remote** (`github.com/flow6979/dispatch-sandbox`) to push to.
- It lets Dispatch practice its full workflow: branch → change files → commit → open PR → merge.
- Because everything here is disposable, there is no risk to production code.

## How the pieces fit together

The repository is intentionally minimal. Every file is either documentation or metadata:

| File | Purpose |
|------|---------|
| `README.md` | One-line statement of intent: a throwaway repo for testing Dispatch "real-mode" task execution, where PRs are auto-generated by the Dispatch runner. |
| `LICENSE` | MIT license (added by a Dispatch-generated PR — see history below). Gives the sandbox a standard open-source license. |
| `CONTRIBUTING.md` | Contributor guidance / how to open a PR (added by an earlier Dispatch task; see history). |
| `ORIENTATION.md` | This document. |

There is **no application code, build system, tests, or dependencies** — and that is by design.
The "behavior" being tested lives in the external Dispatch runner, not in this repo.

## What the Git history tells you

The commit history is itself the clearest evidence of what the repo is for — each non-init
commit is a task Dispatch was asked to perform:

```
c760faa  init sandbox                          # bootstrap the empty sandbox
fd039f5  dispatch: Add a CONTRIBUTING.md ...    # a Dispatch task
e24d91f  dispatch: Add an MIT LICENSE file ...  # a Dispatch task
7ee233a  Merge pull request #2 ...              # Dispatch opened & merged its own PR
```

The `dispatch:` commit prefixes and the auto-generated PRs are the fingerprints of the
runner doing its job. Reading the log top-to-bottom is effectively a log of test runs.

## TL;DR

`dispatch-sandbox` is a disposable GitHub repository whose only job is to be a realistic,
low-stakes target for the Dispatch automation runner to make commits and open pull requests
against. If you are looking for product logic, there is none here — the interesting system
is Dispatch, and this repo is simply where it proves it works.
